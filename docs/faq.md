# 常见问题

## 这个工具能替代律师吗

不能。它只比较许可证条款层面的常见差异，帮你把候选缩到两三个，最终取舍仍然要人来做，涉及商业合同和专利布局时请咨询法务。

## 为什么没有 BSD-2-Clause

数据集优先覆盖“行为差异明显”的许可证。BSD-2-Clause 与 MIT 在义务上几乎等价（差别在宣传条款的措辞），收录它只会让同分并列更严重。如果确实需要，按 `docs/design.md` 的步骤加一条即可。

## 为什么 `hobby` 推荐的是 BSD-3-Clause 而不是 MIT

两者同分（都是宽松 + 文本短），排序规则在并列时按 SPDX 字母序，所以 `BSD-3-Clause` 排在前面。这不是“更好”，只是稳定排序的结果。要打破并列，回答问题时把“是否希望被法律上更简洁的文本覆盖”这类偏好权重调高，或者直接看义务清单。

## 分数一样怎么办

看义务清单，问三个问题：

1. 我能不能长期维护它要求的额外文件（比如 `NOTICE`）？
2. 下游是我的用户，还是我的竞争对手？
3. 这个项目未来会不会商业化？如果会，现在选的许可证能不能改？

许可证只能往更宽松的方向改，不能往回改：已经从 MIT 发布的版本，别人可以永久按 MIT 使用。

## 能不能中途换许可证

可以，但有边界。你拥有全部版权（或所有贡献者都同意）时，可以在新版本上换成别的许可证；已经发布的旧版本仍然按旧许可证有效，任何人都能继续基于旧版本分发。所以“先 MIT 上车，以后再说”是可行的，反过来（先 GPL 后闭源）几乎不可行。

## 为什么不直接调用 GitHub API 判断

那需要联网和令牌，而本项目刻意做成离线工具：课程机房里断网也能跑，也不会因为 API 变更而失效。数据文件是静态的，更新靠 PR。

## `--json` 的输出稳定吗

字段名在 0.x 版本内保持稳定，新增字段只追加不删除。`score` 的数值可能随权重调整变化，脚本里请只依赖排序和 `spdx`，不要硬编码分数。
